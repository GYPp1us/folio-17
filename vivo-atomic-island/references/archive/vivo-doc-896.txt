
一、架构设计





说明：


整体使用系统通知方案（本地发送通知 或 push更新通知）

应用客户端需要接入VPush SDK，获取设备token（regId）

详见：
https://dev.vivo.com.cn/documentCenter/doc/365#w1-93569122



基本步骤：


在本地发通知，携带规定原子通知字段，可在系统创建原子通知。
详见第3章节
。

原子通知创建完成后，将设备token(regId)、notifyId、场景scene信息上传应用服务器。

应用服务器可以通过VPush服务器规定的字段更新/结束原子通知。


二、数据协议

2.1 核心参数

原子通知核心数据字段






参数





是否必填(Y/N)





参数类型





描述






notification.superx.operation



Y



int



原子通知生命周期

0：创建原子通知

1：更新原子通知

2：结束原子通知





notification.superx.showNotify



N



boolean



原子通知展示失败时是否需要展示成普通通知

默认值是true 

true:会展示成普通通知

false：不会展示成普通通知





notification.superx.template



Y



int



原子通知类型 

1：强调信息模板

2：进度可视化模板 

3:  左右信息对称模版

4：基础模版

5：导航模版





notification.superx.baseInfos



Y



Bundle



基础信息参数，通过bundle设置。需将4.4章节的模版数据塞到此bundle里面。





notification.superx.infos



Y



Bundle



原子通知对应template的参数，通过bundle设置。需将4.5/4.6/4.7章节的模版数据塞到此bundle里面。





notification.superx.shortInfos



Y



Bundle



小卡和OriginB锁屏模版参数信息，通过bundle设置





notification.superx.capsule



N [*不支持岛的设备会默认取这里的信息作为状态栏触点]



Bundle



胶囊模版的参数，通过bundle设置。需将4.2章节的模版数据塞到此bundle里面。





notification.superx.island



N [*支持岛的设备会默认取这里的信息作为状态栏触点]



Bundle



OS5.0原子岛模版的参数，通过bundle设置





notification.superx.clickResp



Y



PendingIntent



对大卡/小卡/胶囊点击事件的定义，B锁屏是拖动后触发、点击空白位置。





notification.superx.scene



Y



String



原子通知的场景 

MOVIE 电影

HEALTH_REGISTER 挂号

TAXI  打车

TAKEOUT 外卖

DELIEVERY 快递

NAVIGATION 导航

CAR_STATE 车机状态

METTING 会议日程

TRAIN 火车

FLIGHT 航班 等





notification.superx.keepDuration



N



int



单位s。最长存档显示时间3600s（1小时）。表示原子通知结束后，还需要保留显示多久

默认不存档显示





notification.superx.changedRecord



N



int



更新的顺序，若后续来的更新信息此值小于当前值，则丢掉





notification.superx.newNode



N



int



用来传递新的节点【如接单是1，送外卖是2】，用途是 胶囊等处可以展示重要的节点





notification.superx.displays



N



int



参数含义如下：

如果不传，默认触点【4*2卡片默认是全触点， 4*1卡片默认 通知&状态栏】，例:传0x111 显示 【通知&锁屏&状态栏】

全触点包括：通知/锁屏/状态栏/桌面组件/熄屏/魔盒

0x001 ： 通知

0x010 ： 锁屏

0x100 ： 状态栏

0x1000 ： 桌面组件

0x10000 ： 熄屏

0x100000 ： 魔盒

0x1000000 ： 小v建议





notification.superx.sound



N



boolean



创建原子通知时是否响铃true:创建时响铃【默认值】

false:创建时不响铃





notification.superx.dismissWhenKill



N



boolean



杀进程（Kill或force-stop）时此原子通知是否被清除

true:会被清除

false:不会被清除【默认值】





notification.superx.

customSuperx



N



String {json}



原子通知的扩展信息【如接入小v建议】

{需要特殊对接协议} 封装字段示例如下


{
"key1":”value1”
...
}

三、Demo代码

3.1 本地创建
示意
：（具体的参数按照上面的要求传）


Bundle b = new Bundle();
b.putInt("notification.superx.operation", 0);
b.putBoolean("notification.superx.showNotify", true);
b.putInt("notification.superx.template", 1);
b.putParcelable("notification.superx.clickResp", mPendingIntent);
b.putString("notification.superx.scene", "HEALTH_REGISTER");
 
Bundle baseInfo = new Bundle();
// icon
baseInfo.putParcelable("notification.superx.baseInfos.icon", icon);
// title & content
baseInfo.putCharSequence("notification.superx.baseInfos.title", title);
baseInfo.putCharSequence("notification.superx.baseInfos.content", content);
 
b.putBundle("notification.superx.baseInfos", baseInfo); //CHANNEL_NORMAL通知渠道
Notification notification = new NotificationCompat.Builder(mContext, CHANNEL_NORMAL)
		.setContentTitle(mContext.getText(R.string.traditional_notification_title))
		.setContentText(traditionalNotificationContent)
		.setSmallIcon(R.mipmap.ic_launcher)
		.setExtras(b)
		.build();
mManager.notify(notificationId, notification);

3.2 本地更新：

代码同本地创建，需要更新字段
notification.superx.operation
为1


b.putInt("notification.superx.operation", 1);
// 更新通知
mManager.notify(notificationId, notification);




3.3 本地结束：

（1）
NotificationManager
的notify方法：代码同本地创建，需要更新字段
notification.superx.operation
为2，可以通过配置“
notification.superx.keepDuration
”来设置结束后继续显示一段时间（最长1小时）。

（2）
NotificationManager
的cancel方法：如果想直接取消掉这个原子通知，后续也不需要再展示。
mManager.cancel(tag, id) 
   方式取消，传一个固定 tag（"VIVO_SUPERX_TAG"）进来。

4.1 鉴权

原子通知远程更新接口与普通通知同属一套鉴权方式，详情可见vpush开放平台接口文档：
https://dev.vivo.com.cn/documentCenter/doc/362#w2-24351194


要想调用PUSH接口，任何接入方都要有个鉴权操作。其他接口header中必须携带该参数。

接口返回的参数authToken，一个appId可对应多个token，24小时过期，业务方做中心缓存，1-2小时更新一次。

限制：频率限制，单个app 10次/s。超频返回错误码10093。

URL





编码方式





协议

Utf-8

curl -X POST -H     'Content-Type:application/json' -d   '${your_request_body}'     https://api-push.vivo.com.cn/message/auth

sign生成示例

（1）生成sign的示例参数如下：


appId:10004
appKey:25509283-3767-4b9e-83fe-b6e55ac6243e
timestamp:1501484120000
appSecret:7265f2a4-ebbb-44bf-88b9-b03e67dfdc21


（2）按照顺序拼接参数：


1000425509283-3767-4b9e-83fe-b6e55ac6243e15014841200007265f2a4-ebbb-44bf-88b9-b03e67dfdc21


（3）MD5成小写字母：


sign = MD5(1000425509283-3767-4b9e-83fe-b6e55ac6243e15014841200007265f2a4-ebbb-44bf-88b9-b03e67dfdc21)


（4）得到的最终sign字段：


fe3b46a2befc60334c2388676a752bd6



接口定义


输入参数：







属性名字





类型





是否必填(Y/N)





描述






appId



int



Y



用户申请推送业务时生成的appId





appKey



string



Y



用户申请推送业务时获得的appKey





timestamp



long



Y



Unix时间戳 做签名用，单位：毫秒，且在vivo服务器当前utc时间戳前后十分钟区间内。


该timestamp要与生成sign时使用的timestamp值相同。






sign



string



Y



签名 使用MD5算法，字符串拼接（appId+appKey+timestamp+appSecret），然后通过MD5加密得到的值（字母小写）。


如sign生成示例所示，可使用示例参数生成sign，与示例结果对比是否一致，如一致表示生成正确，如不一致请排查按sign生成示例指引排查。

属性名字





类型

int



接口调用是否成功的状态码 0成功，非0失败

string



文字描述接口调用情况

string



当鉴权成功时才会有该字段，推送消息时，需要提供authToken，有效期默认为1天，过期后无法使用。一个appId可对应多个token，24小时过期，业务方做中心缓存，1-2小时更新一次。

五、重要说明

1、兼容性设计：原子岛的数据和状态栏胶囊的数据都需要发，因为存在Flip这种机型，外屏还是会显示胶囊。

2、原子通知Icon资源无更新，可以不传，复用之前的资源

3、多语言场景问题解决方案：建议app将本地的语言环境上传给服务器，后续服务器更新使用对应的语言，至少要适配中英文。

4、原子通知结束，且无存档期的情况下，只需要传结束（notification.superx.operation）标识，其他数据可不传

5、颜色异常的默认值问题，默认值可以写成0x0（alpha为0，视为异常值）

6、如何判断原子通知设置界面某个场景开关状态
【注：可以用此状态判断是否发送原子通知】


系统在NotificationMananger.java 中新增接口，可以通过反射调用

// 返回true，代表开关打开，反之，关闭。

public boolean getSceneStatus(String pkgName, String sceneName)


示例：



try {
	Class clz = Class.forName("android.app.NotificationManager");//声明调用的类
	@SuppressLint("SoonBlockedPrivateApi")
	Method getSceneStatus = clz.getDeclaredMethod("getSceneStatus", String.class, String.class);//声明方法
	getSceneStatus.setAccessible(true);//方法设置为可访问
	Object nm = MainActivity.this.getSystemService(Context.NOTIFICATION_SERVICE);//重点：声明调用的类，必须要有相关的实例对象
	boolean result = (boolean) getSceneStatus.invoke(nm, "com.vivo.ele", "TRAIN");//反射执行相关方法，注意换成自己的包名+场景！！
} catch (ClassNotFoundException | NoSuchMethodException | IllegalAccessException |
		 InvocationTargetException e) {
	e.printStackTrace();
}




7、谨慎使用 
https://developer.android.com/reference/android/app/Notification.Builder#setAutoCancel(boolean)
 方法，会造成从通知栏点击原子通知后，原子通知被系统cancel掉。

8、APP需管理好原子通知的渠道（NotificationChannel），如创建渠道和删除渠道的时机，无渠道会造成发送失败,不能出卡。如果删除渠道，也会造成原子通知被清除！

11、通知渠道管理问题（NotificationChannel）


（1）确保先有渠道（NotificationChannel），再发原子通知。



（2）APP需管理好原子通知的渠道（NotificationChannel），如创建渠道和删除渠道的时机，无渠道会造成发送失败,不能出卡。如果删除渠道，也会造成原子通知被清除！


12、接入方需要注意token（regId）注册和解注册的时机，并保证将regid跟设备的映射关系，是最新的。防止出现推不到对应设备上的问题。

13、token一键换机场景，出现新机器下单，仍向旧机器发push情况


解决方式：


（1）升级push sdk至500级及以上版本

（2）每次CP冷启动，调用一次turnonpush接口调用成功后，通过getregid接口拿到本次的regid并且，及时同步服务端即可。

目前发现一键换机场景，业务应用的数据会迁移，如果业务有对regid做持久化，那么一键换机很容易出现regid映射错误

14、数据有效期问题

服务端：timeToLive  建议使用默认的24小时，自定义的话至少30分钟以上

15、端侧发送图片Icon的宽高，不大于1000*1000

16、
不要判断通知开关状态！

vivo有小v建议组件卡片的形态，接入原子通知同时也可以在建议组件卡片展示，如果需要了解接入关注customSuperX字段，并向vivo商务侧了解。
